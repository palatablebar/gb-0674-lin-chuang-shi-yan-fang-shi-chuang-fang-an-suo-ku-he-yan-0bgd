# 访视与冻结定义

样例均为虚构编号，无身份信息。受试者入组日期由subjects表唯一确定，记录中的入组基准必须完全一致。

## 业务日裁决（唯一日历口径）

海外中心记录只带当地时刻和偏移，跨午夜换算到研究时区后日历日会前后挪一天。正式裁决：**业务日一律取研究时区 Asia/Shanghai 的日历日，称为“采用日”(adopted_date)**，方案切换、访视排窗、偏离复核、锁库检查共用这同一日历结论；中心当地日(local_date)与当地偏移(local_offset)只作证据同屏展示，不参与任何判断。锁库要求跨中心同一日历结论，当地门诊日由各中心偏移各自决定，无法跨中心对账，故不作为业务日。

时间证据四件套全程保留、随冻结包导出，原始依据不丢失：`at_raw`（原始时刻含偏移）、`at_utc`（UTC即时刻）、`local_offset`+`local_date`（中心当地，仅证据）、`adopted_date`（研究时区采用日，唯一业务日）。时刻解析统一收口在 `app/calendar.py`，无偏移时刻直接拒绝(BAD_TIME)，禁止其他模块自行做时区换算。

复检 72 小时是真实时长问题，按 UTC 即时刻差值 `elapsed_hours` 判断（0 < 时差 ≤ 72 小时），**不按采用日或当地日取整**；即使当地日历相差 3 天，只要真实时差不超限仍有效，反之真实时差超限即阻断。

源数据或上下文变化会改变 sha256 摘要并生成新批号，旧批结论不再代表新源；同批不可变快照重跑批号、sha256 与正式结论完全一致。规则版本见 manifest.rule_version。

采样日期和入组日期的研究时区日历日之差为访视日；时刻先统一UTC再做研究时区换算。
方案选择按当前受试者assignment和该次发生时刻（研究时区生效窗，整日边界等价于采用日比较）查半开生效窗，匹配必须唯一，不能使用全局最新方案，也不能用中心当地日。v1访视V1=[5,10)、V2=[12,17)；v2为[6,11)、[13,18)。受试者00001于10月10日转v2，其他受试者仍用v1。
PRIMARY计入访视完成，RETEST只替代该次测量值。首次记录必须唯一且在访视窗内。缺首次访视、重复首次和窗外访视均阻断，复检不能填补漏访或消除原偏离。
复检须引用同受试者同访视的PRIMARY，晚于原采样且不超过72小时（真实时差），版本必须更高。同最高版本复检冲突时保留原结果并阻断。所有检验值以mg/dL输出，g/L乘100。
锁库须所有规定访视完成，无偏离、复检问题和隔离行。冻结包包含每条选定结果、原始行号、方案版本、访视窗与完整时间证据。此工具只验证试验数据完整性，不做诊断判断或生产锁库。

## 样例集

dirty/clean/legacy 三个样例的中心均在研究时区(+08:00)内；`overseas.csv`（海外跨午夜批）含 +09:00、-05:00 两个海外中心及一条 UTC(Z) 记录，专门演示同一访视在“中心当地日”与“研究时区采用日”下结论相反的情形（如 OS02-V2 当地日窗内、采用日窗外；OS03-V1 当地日提前、采用日窗内），以及复检按真实时差裁决（OS03-V1-Z 当地日相差3天但70.5h仍有效）。
